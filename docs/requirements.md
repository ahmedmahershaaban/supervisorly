# Requirements

Derived from what actually broke in Ahmed's manual process. Each pain point is evidence
from the corpus plus the capability the tool must therefore have.

## Prior art — what Ahmed already built

### The reusable prompt
PROMPT_Zhijing_DeepDive.md is a single self-contained OSINT prompt with 6 fixed sections in order: ROLE (ethics + provenance preamble: public professional info only, 'Cite a URL + date for every item', say so explicitly if blocked, 'never invent') -> TARGET (the ONLY professor-specific block: name, rank, university, lab, chair, prior institutions, research areas) -> ANCHOR LINKS ('start here, then follow links outward': site, CV, Scholar, GitHub, key repo, Medium, LinkedIn search string) -> a hard output contract ('DELIVER YOUR ANSWER AS 5 SEPARATE MARKDOWN FILES, exactly with these headers') -> five '=== FILE N: <name>.md ===' blocks each with its own field spec and fixed cardinality (15 most-cited papers, 10 frequent co-authors, 5 most recent papers, 10 best posts, 8-12 recommendations) -> RULES (cite URL+date on every fact; mark anything you couldn't access; do not fabricate). The five files form a DAG, not a list: FILE 1 (link discovery, confirms the X handle from her own pages) feeds FILE 2 (Twitter, needs the confirmed handle); FILE 3 (Scholar) and FILE 4 (GitHub) run in parallel; FILE 5 is a synthesis node consuming all four and required to tie every recommendation to a named upstream source. FILE 2 defines a reusable 5-bucket social taxonomy (A recruiting/openings, B PhD & application advice, C what she values in people, D research threads now, E mentorship/community/diversity) plus a ranked star-marked top-10. The header states the parameterisation seam explicitly: 'Reusable: swap the target's name and anchor links to run it on any other professor.' Usage notes admit the failure modes up front: run one FILE at a time if the extension chokes; be logged into X first; Scholar blocks automated scraping. Assumed tooling is a logged-in browsing Chrome extension (Claude for Chrome / Perplexity / Monica / MaxAI), i.e. session-cookie reuse, not APIs.

### What it produced
The run produced all 5 files on disk in 'Zhijing Jin profile/' (verified: zhijing_profiles_and_links.md 3.2KB, zhijing_twitter_5yr.md 9.7KB, zhijing_scholar.md 3.0KB, zhijing_github_phd_guide.md 3.8KB, zhijing_application_insights.md 3.2KB). Quality was high where the source was reachable and honestly degraded where it was not. Wins: a 3-column link table (Platform | Exact URL | Where she links it) with the handle confirmed from her own header/footer and explicitly labelled 'Not guessed'; a 'Not found on her own pages (marked so you don't chase)' negative cache marking LinkedIn/Semantic Scholar/Medium UNCONFIRMED; ~16 tweets with date + one-line topic + permalink + engagement counts + 'Verbatim:' quoted text + in-thread reply + '=>' derived takeaway; a full read of her 1,077-star PhD-advice repo with TOC, direct quotes, sibling repos and star counts (dated 'stars as of 2026-07-20'); and 13 numbered, individually source-cited application insights (entry route, required coding signal, funding channels with amounts and deadlines, admitting departments CS/ECE/Stats, visa/export-control eligibility, reapplication rule, soft criteria). Failures were recorded in-band rather than silently: Google Scholar returned the automated-query block page, so zhijing_scholar.md opens '⚠️ ACCESS BLOCKED', enumerates exactly which fields could not be retrieved (total citations, h-index, i10, top-15 papers, co-author list), notes 'No cache/proxy workaround used', and substitutes a labelled proxy section ('use as proxy, not Scholar' / '(NOT the Scholar co-author frequency ranking)'). Two real defects: the insights file is physically truncated mid-word at item 13 ('(ar'), proving there was no completeness check; and ~16 of 742 tweets were captured with no pagination or completeness guarantee.

### What he had to fix by hand
Everything the automated pass could not do, Ahmed did by hand, and the hand-fixes are the specification for the new tool. (1) Metrics recovery: zhijing_scholar_VERIFIED.md holds hand-copied ground truth (163 papers, 6,732 citations, h-index 32, ~321 distinct co-authors) because Scholar was blocked. (2) Entities the prompt never asked for: PROFILE_Zhijing_Jin_Detailed.md adds the lab roster (20 current members with level, topic, prior institution, co-supervisor, fellowship, concurrent industry role), all-time mentee statistics (~109: 13 PhD / 41 Master's / 35 undergrad / 18 pre-doc / 2 postdoc, 30+ nationalities), and a bidirectional 'where her people come from and go' block naming ~17 destination companies and ~11 destination PhD programs; 03_Students_Lab_Members_Found.md does the same lab-page-only extraction for five more UofT labs. (3) A derived layer: ANALYSIS_Zhijing_DeepDive_Intel.md turns raw scrapes into recruiting cadence, deadlines and the two fellowships she helps applicants win. (4) Program/admissions data, which the deep-dive prompt never requested at all, was built in a separate ~10-file track (File28-File32, File_37, File_40, VERIFIED_UofT_Admissions_Facts.md) with a 🟢/🟡/⚠️ verified-vs-inferred legend, and never joined to professors by any key. (5) Re-verification by hand: UofT_Professor_Status_Recheck_2026-07-19.md and Vector_York_TMU_UTM_UTSC_Recheck_2026-07-19.md re-fetch every professor 9 days after the 2026-07-10 dashboard baseline, tag each row (unchanged) / NEW: / CHANGED ->, and add a monthly WATCH-LIST of 6 URLs. (6) Corrections logged rather than silently patched: a hallucinated Zhijing<->Dan Roth co-authorship retracted, 'Zhijing has no Master's', 'Olga Veksler is at Waterloo not Western', 'Vector Scholarship is MSc-only not PhD', 'OGS is NOT domestic-only'. (7) Hazards found and hand-flagged: wanglab.ai redirecting to the ad-squat domain bulsis.net, Zemel's page still showing a 2021-2022 leave notice, Urtasun's page ~5 years stale, Kamath departing to NYU.

### His existing multi-agent skill
'career-scan' (verified on disk at 'files (1)/', 15 files) is a shipped multi-agent Claude Code Skill and the architectural template. Two tiers: an invocable orchestrator (.claude/skills/career-scan/SKILL.md, frontmatter = name matching the folder, a long 'Use this skill whenever...' trigger description, disable-model-invocation: false) plus five worker subagents in .claude/agents/*.md with isolated context windows and per-role model tiers (haiku flutter-inventory, sonnet flutter-architecture + flutter-features, opus flutter-custom-work + evidence-auditor). The pipeline is deterministic-before-LLM: discover_projects.py enumerates targets and assigns a collision-safe report_key -> classify_provenance.py answers 'is this even yours?' with an ordered verdict ladder (AUTHORED_SOLO ... CLONED_UNTOUCHED) plus a machine verdict AND a human 'meaning' string licensing what may be claimed -> collect_facts.py emits a versioned facts.json where every count carries bounded 'path.dart:LINE' evidence and every derived number carries the exact command that produced it (timeline_source, shortlog_source, pubspec.method) -> the four agents interpret only ('read it first and treat every number in it as ground truth; never compute your own counts. Return <=10 lines. Do not paste the report back.') -> validate_report.py --strict mechanically reopens every citation and cross-checks every number, emitting {verdict, stats, findings[]} with BROKEN_CITATION / ORPHAN_NUMBER / UNSOURCED_METRIC / OWNERSHIP_OVERSTATED -> an adversarial opus evidence-auditor does judgement checks a script cannot, with a skeptical-staff-engineer persona, a sampling policy (100% of metrics/AUTHORED/superlatives, 25% of the rest), a 4-value verdict vocabulary (VERIFIED/WEAK/UNSOURCED/CONTRADICTED) each with a mandated action, and separation of duties ('Report only; the orchestrator applies fixes'). It ends in a typed contract, skills.json, where a `verified: true` boolean gates what a downstream consumer may submit, plus an `aliases` array for matching and a `do_not_claim` blocklist. Safety is enforced by the harness (settings.json deny/ask/allow, Bash and PowerShell mirrored, Edit denied by extension, secret reads denied) not by prompt text: 'an agent file saying read-only is an instruction to the model. Permission rules are enforced by Claude Code itself.' Context economics: five projects x 400 files costs the orchestrator ~50 lines. The governing sentence is 'The model never gets to originate a number.'

### His two dashboards
Two exist and they are not comparable. dashboard.html (~110KB, ~2026-07-10) is the real prior art and is far stronger: a zero-dependency single-file 'Toronto AI Grad School Command Center' with vanilla JS, hand-written CSS custom properties, light/dark tokens, per-university brand colours, an esc() escaper, eight tabs driven by a TABS array + render() switch, and all data inlined as JS literals — PROFESSORS (104 hand-profiled records with keys name, inst, campus, tags[], tier, vector, chair, quote, note, action, flags[], src), VECTOR_AFFILIATES (106 rows), SCHOOLS (8, with directEntry/advisor/gre/english/intakes/deadline/fundingIntl/fundingNote/verdict), SCHOLARSHIPS (6), TIMELINE (11), FLAGS (16 crit/warn/info), and 4 raw name dumps. Its one real computation is a funding bar chart normalised against a hardcoded max of 47498. Its fatal weakness is that ranking is not computed at all: `tier` (1-4) is hand-typed per professor and SHORTLIST_ORDER is 20 hardcoded name strings joined by exact match with .filter(Boolean), so a typo silently drops a professor; the stated blend ('current/explicit recruiting signal, funding accessibility, direct-entry-PhD compatibility, and subfield strength') exists only in prose. Other gaps: no professor URLs or emails anywhere, no lastVerified field, `src` provenance stored but never rendered, no stable IDs, students/companies/publications trapped in the `note` free text, 122 uncontrolled subfield tags, single-select filters only, filter state not in the URL, full innerHTML re-render per keystroke, and no export but window.print(). It does carry two guardrails worth keeping verbatim: 'Nothing here has been sent anywhere... This dashboard is a decision tool — the actual emailing is yours to do' and the not-financial-or-immigration-advice disclaimer. The second dashboard, 'Mila Mission Control' (mila_mission_control.jsx 1,195 lines; mila-mission-control (1).html 356KB esbuild bundle with React 18 + lucide inlined), contains ZERO professor data ('professor' = 0 hits) — it is a study-plan tracker. Its value is purely architectural: five-level hour-weighted roll-up stats of identical shape {total, doneH, pct}, an SVG orrery of satellite donuts, a dependency-aware Gantt with sequential 'spine' tracks plus parallel compressed tracks and a live pace slider, a GitHub-style heatmap normalised to personal max, a window.storage shim so the same bundle runs in a Claude Artifact and standalone, and — most reusable — an explicit LLM hand-off contract: an Export JSON payload carrying a denormalised `summary` block plus a buildAskText() 'copy question for Claude' template. Its richest record shape (k/t/h/mn/time/src/link/note/deliv) maps cleanly onto a provenance-carrying professor field: src = where the fact was scraped, link = the source URL, note = analyst commentary, deliv = why this professor is a fit.

## Pain points (ranked)

### P1. Nothing is structured. Provenance exists only as prose, so the corpus cannot be filtered, sorted, joined, diffed or validated — the single biggest blocker to a dashboard.

**Evidence:** Cluster 2 gaps: 'Everything is unstructured Markdown prose — no JSON/YAML frontmatter, no stable field names, no IDs. Nothing here can be loaded into a filterable dashboard without re-parsing.' Cluster 1: 'cite URL + date on every fact produces markdown tables and inline citations that cannot be filtered, sorted, or joined.'

**Therefore:** Provenance must be a first-class data structure, not a formatting convention: every field value is a Claim {value, quote, source_url, snapshot_hash, offsets, observed_at, confidence, extractor}. Markdown becomes a rendering of the database, never the database.

### P2. The highest-value field — is this professor recruiting for MY cycle — is the least reliable. Statements are undated, cycle-ambiguous, or sitting on pages years stale, and a naive scraper reads all of them wrong.

**Evidence:** Recheck cluster: 'Every "Applications Closed" status you'll see still refers to the Fall 2026 intake.' Zemel's page still says 'I am on-leave from the University of Toronto in 2021-2022'; Urtasun's page is ~5 years stale yet says 'looking for motivated students'; Fidler's is 'undated/evergreen... not confirmed current'.

**Therefore:** RecruitingSignal must be its own entity carrying verbatim quote + state + target_cycle + datedness + observed_at + a freshness penalty, and the pipeline must normalize every scraped status against the user's target cycle before display. 'No signal found' and 'source unreadable' must be distinct states from 'not recruiting'.

### P3. Every university directory is structurally different — rendering mode, URL patterns, slug conventions, filters, field richness, failure modes — so there is no single scraper.

**Evidence:** Cluster 8/9: Vector's roster is virtualized and lost ~50 of 106 names to scroll; York funding accordions failed across two whole sessions; slugs are non-derivable ('mab' for mbrubake, 'ruth' for uruth); TMU 404'd on two guessed department URLs; UofT ECE publishes 'only name + title'; McMaster exposes an 'Accepting graduate students' checkbox nobody else has.

**Therefore:** A per-institution DirectoryAdapter is a first-class, version-controlled artifact: rendering mode, API endpoint if any, learned selectors, slug pattern (learned, never guessed), quirks, robots policy, and a completeness checksum against site-declared counts. Adding a country means adding adapters, not editing the core.

### P4. Citation validation does not transfer from files to the web. career-scan's validator works because 'file:LINE' persists on disk; web pages mutate, move and vanish.

**Evidence:** Cluster 4 gaps: 'Web sources are mutable and can vanish — validate_report.py's model does not transfer without an archived-snapshot/content-hash mechanism.' Real cases: wanglab.ai now redirects to the ad-squat bulsis.net; a WordPress API that produced the authoritative 106-row roster later 404'd.

**Therefore:** Every fetch stores a content-hashed snapshot with character offsets for the cited sentence. The validator re-opens the snapshot (not the live page) to confirm the quote, then separately re-fetches to detect drift. Link-health checks must quarantine hijacked/parked domains rather than ingesting ad content as professor data.

### P5. Students and companies — two headline features — have almost no reliable public source. Rosters are absent, undated or stale; alumni destinations are published by a small minority of labs; corporate funding of labs is essentially never published.

**Evidence:** Cluster 11: 'None of these pages listed direct personal emails for students, only names'; year_joined is NOT_FOUND anywhere; prior institution available for 1 lab in 6; only ~2 of 6 sampled labs published any alumni outcomes; 'No corporate funder is ever named for a lab' beyond one 'Funded by: Intel, AMD, LG, Sony' block. Cluster 2: 'COMPANIES the professor has worked with... essentially absent.'

**Therefore:** Ship these as explicitly partial features with honest nulls and per-lab quality flags (current / stale / absent), not as columns that silently look empty. Derive company links from four separately-typed edges — professor employment, lab funder, student fellowship, alumnus placement — and never merge them into one fake 'works with' field. LinkedIn is off-limits; do not design around it.

### P6. There is no join key between professors and the programs, funding and admissions rules that decide whether an application is even possible.

**Evidence:** Cluster 1 gaps: 'Funding/admissions data lives in a completely separate set of ~10 files with no join key to professors — the deep-dive prompt never asks for the program's admissions requirements or funding.'

**Therefore:** Model Person -> admitting_routes -> GraduateProgram -> ApplicationCycle -> FundingItem as real edges so the dashboard can eliminate on hard gates (direct-entry availability, language bands, international funding, nationality restrictions) before it ever ranks on fit.

### P7. Ranking was never computed. Tier and shortlist were hand-typed, so no user can re-rank on their own priorities and a typo silently drops a professor.

**Evidence:** dashboard.html: `tier` is a hand-assigned 1-4 integer, SHORTLIST_ORDER is 20 literal names resolved by exact string match with .filter(Boolean); the stated blend ('recruiting signal, funding accessibility, direct-entry compatibility, subfield strength') 'is documented in prose but never implemented in code'.

**Therefore:** FitAssessment must be computed from claim-backed components with user-set weights, must show its components and its evidence, and must carry a confidence-of-score so sparse records cannot outrank complete ones. Hard eligibility gates run before scoring.

### P8. Blocked and authenticated sources break the metrics and social layers outright, and per-source reliability varies wildly for the same person.

**Evidence:** '⚠️ ACCESS BLOCKED... Google's automated-query block page on 2026-07-20'; 'Be logged into X/Twitter in that Chrome tab... or the extension only sees a login wall'; 'Semantic Scholar is unreliable for her (shows only 34 papers)' against a true 163.

**Therefore:** Default to open, documented APIs (OpenAlex, Crossref, arXiv, ORCID, DBLP, GitHub REST) instead of scraping blocked properties; store one metrics row per source with the source named and never blend counts; and provide a first-class manual-paste path with an explicit 'manually entered' confidence for the fields no API can supply.

### P9. No freshness or change-detection mechanism. Re-verification meant re-writing entire files by hand on a 9-day cadence, and the watch-list was a human cron job.

**Evidence:** UofT_Professor_Status_Recheck_2026-07-19.md re-checks everything 'relative to the dashboard baseline of 2026-07-10'; the watch-list says 'check monthly / before finalizing report' with no mechanism; 'files are stamped by hand... No diffing, no change detection on openings/deadlines.'

**Therefore:** Per-field observed_at plus append-only claim history, a normalized-quote diff to emit change tags (unchanged / NEW / CHANGED / disappeared), a re-check scheduler with per-field TTLs (recruiting signal days, deadlines weeks, bibliometrics months, admissions rules per cycle), and an auto-generated watch queue for every not-yet-published cycle.

### P10. Manual scale collapse. Coverage was uneven and unfinishable: cataloguing and verification drifted apart, and whole institutions were never started.

**Evidence:** '72 of 97 Vector Faculty Affiliates remain name-only'; 'Distinguished Postdocs/Visiting Researchers/Grad students NOT captured (by design - too voluminous, 649+ people)'; 'Optional schools (Ontario Tech, Waterloo, McMaster, Guelph) — not started at all'; Group C's 11-question logistics set was run on 1 of 7 schools.

**Therefore:** Coverage must be a tracked entity: expected_n vs harvested_n per target, depth_reached, blocked items, deliberate exclusions with reasons, and an auto-generated ranked backlog. The dashboard shows coverage honestly rather than implying completeness.

### P11. No stable identity. Names are the only join key, and they collide, vary and mis-resolve.

**Evidence:** career-scan needed a separate report_key because 'names collide across forks... and a collision silently overwrites an evidence file'; the corpus hit 'Bo Wang / Boyu Wang — these are DIFFERENT people', a cs.toronto.edu/~anna collision resolving to an unrelated student, 'Konstantinos (Kosta) Derpanis' vs 'Konstantinos Derpanis', and the same professor appearing under different titles in the CS directory, the ECE directory and a cross-appointed list.

**Therefore:** Mint internal IDs immediately, attach external IDs (ORCID/OpenAlex/DBLP) opportunistically, keep name variants as a list, and run explicit entity resolution with a human-review queue for ambiguous merges. Never key a shortlist on a display name.

### P12. Sources contradict each other and corrections propagate badly, so wrong facts survive downstream.

**Evidence:** A hallucinated Zhijing<->Dan Roth co-authorship survived across files; 'Vector Scholarship = MSc only, not PhD' and 'OGS is NOT domestic-only' each needed a dedicated correction file; 'Olga Veksler is at WATERLOO (not Western as previously guessed)'; a personal page contradicting the department page was a recurring pattern.

**Therefore:** Conflicts are records, not merge accidents: retain competing claims, apply a stated precedence policy (official > community; newer official > older community; silence means UNRESOLVED, not a guess), supersede rather than overwrite, and surface unresolved conflicts as a UI badge with both sources shown.

### P13. The most decision-relevant advisor-quality information is not on the web at all.

**Evidence:** ADVISOR_Evaluation_Zhijing_Questions.md marks meeting cadence, feedback style, real workload norms, and what happens when a student struggles as 👀 observe / 🗣️ ask — never ✅ verified-from-research; funding terms carry 'always verify in writing' on the offer letter.

**Therefore:** Model 'manual-only' as a real confidence level with an explicit 'unknown — ask' state, a generated question list, and a suggested contact set (current students, grad director). The tool must never fabricate these fields to fill a card, and must never auto-contact anyone.

## Genericity challenges

Concrete obstacles to working in any country, not just Anglo CS departments.

1. Directory discovery has no universal pattern. Faculty lists live at /people, /faculty, /staff, /team, /academics, or a national research portal, on a subdomain that may not match the university domain (lassonde.yorku.ca/eecs, not eecs.yorku.ca), and in non-English sites under localized paths (personal, mitarbeiter, enseignants-chercheurs, 教員). Discovery must be a search-and-verify step per institution, not a URL template.
2. Language and script. A country-scoped run will hit non-English faculty pages constantly: research areas, recruiting statements and admissions rules must be detected, translated for extraction, and stored with both the original verbatim text (which is the evidence) and the translation (which is the searchable field). Names need native-script and transliterated forms, and name order differs by country.
3. Academic rank vocabularies do not map cleanly. Maître de conférences, Privatdozent, Reader, Docent, Professor W2, Associate Professor and Lecturer carry different supervision rights. 'Can this person supervise a doctorate?' is a per-country rule (in some systems only habilitated professors can), and getting it wrong either floods or empties the dashboard.
4. Degree structures differ fundamentally. Direct-entry PhD from a bachelor's is normal in North America, rare or impossible in much of Europe where a master's is mandatory, and the UK/Australia model routes through MPhil upgrade. 'Direct entry' as a boolean is not portable; it needs a per-country entry-route model.
5. Grade-scale normalization is genuinely unsolved. A- vs 3.33/4.33 vs 75% vs 2:1 vs ECTS B vs 92% Egyptian 'Very Good with Honours' cannot be mapped reliably, and the corpus explicitly left this open ('worth asking the department'). The tool must show the raw requirement and the raw applicant grade side by side, with any conversion clearly marked as an estimate.
6. The recruiting-signal culture is not universal. North American professors often publish a personal 'joining' page; in many countries positions are advertised only on a central HR/vacancies portal, a national portal (EURAXESS-style), a funding-body page, or a mailing list — and some systems have no individual-professor recruiting concept at all. The scraper must know which channel a country actually uses, or it will report 'no signal' everywhere.
7. Funding models differ so much that a single 'stipend per year' field is misleading. Guaranteed multi-year packages, per-semester competitive TA slots, externally-funded-only positions, tuition-charged-with-net-negative packages, and salaried employee-model PhDs (common in parts of Europe) are not comparable without a gross/net/duration model and a currency plus purchasing-power note.
8. Nationality, visa and export-control rules are per-country, per-program and legally load-bearing. Some scholarships are restricted by citizenship, some collaborations are restricted by sensitive-technology rules, some programs exclude international applicants entirely. These are hard eliminators that must be modelled per program and per opportunity, not assumed.
9. Bibliometric coverage is uneven across countries and fields. OpenAlex, ORCID and DBLP have strong CS coverage in North America and Europe and much weaker coverage elsewhere and in non-English venues; Google Scholar has the best coverage and blocks scrapers. Metrics-based ranking systematically disadvantages exactly the regions a globally-fair tool should serve.
10. National prestige registries differ. Canada CIFAR AI Chairs and CRC tiers have analogues (ERC grants, DFG, JSPS, ARC Laureate, national academies) but each needs its own adapter, and there is no cross-country equivalence. Prestige must be modelled as a typed Appointment with a per-country program, never as a universal score.
11. Robots.txt, ToS and privacy law vary by jurisdiction. GDPR and similar regimes govern storing personal data about EU-based academics and, far more sensitively, about their students — including a right to erasure. A published open-source tool that ships or republishes personal datasets inherits these obligations wherever it is run.
12. Anti-bot infrastructure is uneven and changes. Some institutions serve static HTML, some are behind Cloudflare, some are SPA-only, some expose a CMS API (WordPress, Drupal, Pure, Converis) that disappears without notice. The fetch layer needs a documented escalation ladder and must record which rung produced each record.
13. Institutional structure itself differs. 'Department' is not universal: faculties, schools, institutes, chairs (in the German sense, where the chair IS the lab), UMR/joint units in France, and hospital-affiliated researchers all break a flat university -> department -> professor tree. The model needs a recursive Unit and a many-to-many Appointment table.
14. Scale. 'All universities in this country' can mean 4,000+ institutions; even one country's CS faculty is tens of thousands of people. Cost, rate limits, crawl politeness and LLM token budget become design constraints from day one, which forces a cheap-enumeration-first, expensive-deep-dive-on-shortlist-only pipeline.
15. Cycle calendars are hemispheric and cultural. Fall intake with a December deadline is not universal; southern-hemisphere academic years, multiple intakes, rolling admission and religious/national holiday calendars all affect deadline parsing and the meaning of a 'closed' status.
